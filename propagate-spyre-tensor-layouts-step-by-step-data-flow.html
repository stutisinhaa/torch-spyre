Overview

The pass has two phases: seed graph inputs with real on-device STLs, then walk operations in topological order and propagate candidate output STLs via compute_layouts. The attribute .layouts written by each iteration is the only communication channel between iterations.

Phase 1 — Seed Graph Inputs

Phase 1 Seed each graph-input TensorBox with its real on-device STL lines 990–1018

Before any operation is visited, every live Spyre tensor passed as a graph input has its concrete SpyreTensorLayout read from hardware and written onto the TensorBox as a single-element candidate list.

for name, real_input in zip(graph.graph_input_names, V.get_real_inputs()):
    if not isinstance(real_input, torch.Tensor): continue
    if real_input.device.type != "spyre": continue   # skip CPU scalars

    stl = real_input.device_tensor_layout()           # ← reads actual STL from spyre tensor
    if stl is None:
        raise Unsupported(...)

    tb = graph.graph_inputs[name]                       # TensorBox(StorageBox(InputBuffer))
    tb.layouts = [stl]                                  # ← seeds the candidate list

This is the only place in the pass where STLs come from real hardware; everything downstream is derived from this seed.

The main path for every compute op is the ComputedBuffer + Pointwise/Reduction row. The key setup before calling compute_layouts:

Phase 3 — _get_prop_args: the inter-iteration bridge

Bridge Package input STL candidates from upstream ops into PropArg structs lines 99–116

For every MemoryDep in rw.reads:

for arg in reads:
    buf    = V.graph.get_buffer(arg.name)
    layout = buf.get_layout()

    if hasattr(buf, "layouts"):
        # Written by a previous compute_layouts call — forward the candidate list
        res.append(PropArg(arg, layout, list(buf.layouts)))
    else:
        # Already a finalised FixedTiledLayout (model weight, constant, …)
        res.append(PropArg(arg, layout, [layout.device_layout]))
Key invariant: buf.layouts is written in Phase 2's loop body after compute_layouts returns. Because operations are in topological order, when we call _get_prop_args for op N, every buffer it reads from op M < N already has .layouts populated.

Phase 5 — Specialised layout handlers

Handler _single_arg_op_layout — called once per candidate input STL lines 209–347
  • Reduction path: derive x_dev_coords and x_stick_expr; call _output_stl_from_stick_expr to try to preserve input layout; if offset or dimension collapses, scan all input dims to find a surviving output stick dim.
  • Pointwise — type conversion (size change): check stick offset, rescale c_size to account for padding, build new SpyreTensorLayout.
  • Pointwise — qfp8ch: propagate device layout and rescale device_size / stride_map for the fp16→fp8 element-count change.
  • Pointwise — identical access: if in_coords == out_coords and same element size, copy device layout verbatim (just swap dtype).
  • Pointwise — general: map input stick expression through output coordinates; fall back to _candidate_output_stls (enumerate non-last dims).

Returns list[SpyreTensorLayout]; outer loop in compute_layouts extends results over all candidate input STLs, then attaches AllSameNode as cost function.

Handler _multi_arg_pointwise_layouts — join point lines 582–691
  • Collect all unique non-zero stick expressions from every candidate STL of every input arg.
  • Fast path: if all inputs have identical coords / size / dtype, propagate the device layout directly (can_use_same_layout).
  • For each offset-free stick expression, call _try_stick_dim: build a dim_order with that stick last, verify it is offset-free on all inputs (via _is_supported_layout).
  • If nothing survived, sweep alternative dims (non-last, divisible by stick_size).
  • Attaches AllSameNode — all inputs and output must share the same stick.
Handler _matmul_layouts — fixed in/out stick constraints lines 516–579
  • Identify x (Input1) and y (Input2) via identify_matmul_inputs (set-arithmetic on free symbols).
  • reduction_var (K) = loop var present in x's index but absent from output's.
  • generated_var (N) = loop var present in y's index and output's, absent from x's.
  • Call find_stick_compatible_input_layout for both: returns existing STL if already correct, else finds a restickify target (Pass 1 / Pass 2 inside that helper).
  • Output STL: stick on generated_var dim; construct FixedInOutNode with both required input STLs.
Handler _exx2_layout / _layernormnorm_layout — fixed reduction-dim stick lines 421–464
  • Both require input stick on the last logical (reduction) dim.
  • Call _check_supported_input_sticks — rejects offset sticks upfront.
  • Call find_stick_compatible_input_layout to find or compute the required input STL.
  • Output STL is fixed: exx2 adds a trailing -1 dim to dim_order and uses ElementArrangement.EXX2; layernormnorm uses standard row-major.
  • Both attach FixedInOutNode — the optimizer will insert a restickify before the op if the input doesn't already have the right stick.
Handler _topk_layouts — reduction with surviving output coords lines 694–742
  • Find reduction_var and surviving_coords (input coords whose symbols map to output dims).
  • For each candidate input STL: if stick carries reduction_var, every surviving coord becomes a candidate output stick dim; otherwise map the stick expr directly to an output dim.
  • Build one SpyreTensorLayout per candidate output stick dim.
  • Attaches AllSameNode.
Handler _clone_layout — materialise contiguous row-major buffer lines 349–418
  • Case 1 (offset-free stick): output is standard row-major; no restickify insertion needed — attach AnyInNode.
  • Case 2 (stick has offset): scan _candidate_output_stls for an alternative stick dim; for each candidate compute whether the input can be restickified to that target via compute_restickify_target_layout; attach FixedInOutNode so the optimizer inserts a pre-restickify.
