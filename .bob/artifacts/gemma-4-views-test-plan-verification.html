2. Test Plan: Gemma-4 Operators & Module Scenarios

View and data manipulation operations are critical in LLMs like Gemma-4. Standard PyTorch size and stride layouts do not naturally support the tiled SpyreTensorLayout structure, which aligns memory in 128-byte sticks. Varied input tensor shape scenarios (aligned vs. padded non-aligned sizes) must be thoroughly validated to prevent memory corruption or compile-path regressions.

3. Test Suite Design

The verification suite implements tests as a standard unittest.TestCase incorporating compare_with_cpu() from the torch-spyre testing framework. This automatically compiles the operations through the Spyre custom Inductor path (using the custom Passes, Stickify layout propagation, and SuperDSC generation) and compares output activations against CPU uncompiled references, checking for bit-exact float16 equivalence.

Composite Attention Module View Flow Scenario

A key test case, test_gemma_attention_module_views, chains the complete view-flow of a Gemma Attention layer to guarantee that back-to-back layout transformations fuse and resolve properly inside the custom compiler without inserting unnecessary host-to-device memory roundtrips:

def attn_view_flow(q_in, k_in, v_in): # Split Q, K, V heads q = q_in.view(B, S, H, D).transpose(1, 2) # view + transpose k = k_in.view(B, S, KVH, D).transpose(1, 2) # view + transpose v = v_in.view(B, S, KVH, D).transpose(1, 2) # view + transpose # GQA expand Key and Value k = k.unsqueeze(2).expand(-1, -1, exp, -1, -1).reshape(B, H, S, D) v = v.unsqueeze(2).expand(-1, -1, exp, -1, -1).reshape(B, H, S, D) # Self-Attention Weights scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(D) attn_weights = F.softmax(scores, dim=-1) # Attention output out = torch.matmul(attn_weights, v) # Reassemble and Flatten out = out.transpose(1, 2).clone(memory_format=torch.contiguous_format) return out.reshape(B, S, H * D)

5. Key Insights & Findings

  • Layout Propagation (Stickify): The compiler stickifier correctly handles non-aligned sequence lengths (e.g., seq_len=67) by mapping them to appropriate padded device-sizes with stride maps. This prevents memory misalignment faults in dxp_standalone.
  • Metadata Elision: Ops such as unsqueeze and expand are correctly recognized as zero-cost metadata-only transformations or optimized lowerings, materializing layouts only before matrix-multiplication operations.
  • Split & Cat Realignment: Joint projection splittings and KV-cache concatenations (even on odd padding points) align with the 128-byte on-device stick boundaries correctly on the compiled path.
